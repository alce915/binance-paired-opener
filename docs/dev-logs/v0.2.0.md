# v0.2.0 — 亢龙多账号开平仓模拟

## 功能范围

- 新增 HMAC-only 多账号安全凭据仓库、DPAPI 加密、文件权限检查、单实例保护，以及本机 bootstrap token 管理接口。
- 新增网页账号导入/管理，采用 `preview → commit` 原子流程；Secret、管理 token 和 credential revision 不进入 Cookie、URL 或浏览器持久化存储。
- 新增可配置批次默认参数：交易对、方向、杠杆、每腿名义价值、轮次和间隔。默认值为 `ETHUSDC`、`LONG`、`100X`、`250000 USD/腿`、30 轮、3 秒。
- 新增逐账号串行的双腿开仓/平仓模拟、强制预检、有限传输重试、幂等控制、lease/fencing、重启恢复、最终配平和 completed 前缀不可变刷新。
- 新增保守容量估算，展示名义仓位占总可开仓位百分比、请求/当前/有效杠杆、双腿投影敞口、完整 leverage bracket、`notionalCoef`、`maxNotionalValue` 与分量 TTL。
- 新增按账号、腿和轮次记录的手续费、点差磨损、市场冲击、时序漂移、配平磨损及价格改善报表。

## 只读保证

本版本的批次功能只读取真实行情和统一账户数据，并在本地账本模拟成交。三账号完整批次的 recording gateway 测试断言所有 Binance 调用均为 `GET`，且不存在 `/order` 或以 `/leverage` 结尾的写路径。代码层未加入批次订单提交、杠杆修改、持仓模式修改或撤单调用。

## 已知限制

- 未执行需要用户真实测试账号和外部 Binance 可达性的只读真实行情冒烟；这不影响自动测试结论，但上线前仍应在受控环境完成。
- 当前网页只接受 Portfolio Margin 统一账户和 HMAC 凭据；不支持 RSA/Ed25519。
- 容量百分比是带安全系数的当前快照估算，不代表 Binance 保证额度；分量过期或缺失时按容量未知阻断。
- 进程内任务 registry 与容量协调器适用于当前单实例桌面部署，不支持多进程横向扩展。

## 后续真实下单边界

未来若从模拟升级到真实下单，必须单独评审并重新验证 API 权限最小化、订单与撤单幂等、交易所回报对账、限频、最大损失/名义价值硬限制、紧急停止、重启恢复、审计留痕和生产发布回滚；不得直接复用本版本的“模拟通过”结论作为真实资金授权。
